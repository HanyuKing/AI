# 早好物爬虫使用说明

## 功能特性

1. **反爬虫措施**
   - ✅ 随机User-Agent（7种不同浏览器）
   - ✅ 随机延迟（模拟人类行为）
   - ✅ 完整的请求头伪装
   - ✅ Cookie自动轮换
   - ✅ 连接池管理

2. **Cookie管理**
   - ✅ 支持多个Cookie配置
   - ✅ 自动轮换使用
   - ✅ Cookie过期自动切换

3. **并发执行** ⭐ 新功能
   - ✅ 多Cookie并发执行，互不影响
   - ✅ 每个Cookie独立线程运行
   - ✅ 线程安全的日志输出
   - ✅ 自动汇总所有线程的执行结果

4. **定时任务** ⭐ 新功能
   - ✅ 每天7点到9点之间随机运行
   - ✅ 自动等待到运行时间
   - ✅ 智能延迟，确保在时间范围内执行
   - ✅ 可配置运行时间范围

5. **人性化延迟** ⭐ 优化
   - ✅ 请求间隔2-4秒（模拟真实人类操作速度）
   - ✅ 随机延迟变化，更自然

## 使用方法

### 1. 配置Cookie和运行时间

编辑 `cookies.json` 文件，添加你的Cookie和运行时间配置：

```json
{
  "cookies": [
    "JSESSIONID=xxx; MM_AIGC_GUEST=xxx; MM_AIGC=xxx",
    "JSESSIONID=yyy; MM_AIGC_GUEST=yyy; MM_AIGC=yyy"
  ],
  "schedule": {
    "enabled": true,
    "start_hour": 7,
    "end_hour": 9
  }
}
```

**配置说明：**
- `cookies`: Cookie列表，每行一个
- `schedule.enabled`: 是否启用定时任务（true/false）
- `schedule.start_hour`: 运行开始时间（24小时制，0-23）
- `schedule.end_hour`: 运行结束时间（24小时制，0-23）

**如何获取Cookie：**
1. 打开浏览器，访问 https://zaohaowu.com
2. 登录账号
3. 按F12打开开发者工具
4. 切换到 Network 标签
5. 刷新页面
6. 找到任意请求，查看 Request Headers 中的 Cookie 字段
7. 复制完整的Cookie值到配置文件中

### 2. 运行爬虫

```bash
cd scripts/zaohaowu
python3 zaohaowu_crawler.py
```

## 工作流程

### 并发模式（当前默认）⭐
1. **加载所有Cookie** - 从配置文件读取
2. **创建线程池** - 为每个Cookie创建独立线程
3. **并发执行** - 每个线程独立执行完整流程：
   - 调用用户信息接口 - 验证Cookie有效性
   - 等待2秒（随机延迟）
   - 获取排行榜数据 - 获取40条数据
   - 提取uniqueContentId - 从返回数据中提取
   - 批量发送want请求 - 对每个contentId发送请求（间隔2-4秒）
4. **汇总结果** - 所有线程完成后统计总结果

**优势：**
- 多个Cookie同时工作，效率提升N倍（N=Cookie数量）
- 每个Cookie独立运行，互不干扰
- 一个Cookie失败不影响其他Cookie

## 反爬虫机制详解

### 随机User-Agent
每次请求随机选择不同的User-Agent，模拟不同浏览器访问。

### 随机延迟
- 基础延迟：2-4秒随机
- 实际延迟：在基础延迟上增加±40%随机变化
- 模拟人类操作的不规律性

### 并发执行（多线程模式）⭐
- 每个Cookie在独立线程中运行，完全隔离
- 每个线程使用独立的HTTP客户端和连接池
- 线程安全的日志输出，不会混乱
- 自动汇总所有线程的执行结果

### 请求头伪装
包含完整的浏览器请求头：
- User-Agent
- Accept
- Accept-Language
- Accept-Encoding
- Referer
- Origin
- Sec-Fetch-* 系列头
- Connection

## 定时任务说明

### 运行时间配置
- **配置文件**：在 `cookies.json` 中配置运行时间范围
- **默认时间范围**：每天 7:00 - 9:00（可在配置文件中修改）
- **运行方式**：在时间范围内随机选择时间执行
- **智能等待**：如果不在运行时间范围内，自动等待到指定时间范围内的随机时间

### 配置文件设置

在 `cookies.json` 中修改：

```json
{
  "schedule": {
    "enabled": true,      // true=启用定时任务，false=立即执行
    "start_hour": 7,       // 开始时间（24小时制）
    "end_hour": 9         // 结束时间（24小时制）
  }
}
```

### 代码中覆盖配置（可选）

如果需要临时覆盖配置文件设置，可以在代码中传入参数：

```python
# 使用配置文件设置（默认）
main()

# 禁用定时任务，立即执行（覆盖配置文件）
main(schedule_mode=False)

# 覆盖运行时间范围
main(start_hour=8, end_hour=10)
```

## 注意事项

1. **延迟时间已优化**：请求间隔2-4秒，更符合人类操作速度
2. **合理配置Cookie数量**，建议2-5个（并发执行时，每个Cookie独立运行）
3. **定期更新Cookie**，避免过期
4. **遵守网站使用条款**，不要过度请求
5. **并发执行时**，每个Cookie会独立获取排行榜数据，可能会处理相同的内容（这是正常的）
6. **线程数量** = Cookie数量，建议不要配置过多Cookie（建议不超过10个）
7. **定时任务**：脚本会持续运行，等待到指定时间执行，适合作为后台服务运行
8. **日志带时间戳**：所有日志输出都包含时间戳，格式为 `[YYYY-MM-DD HH:MM:SS]`

## 故障排查

### Cookie过期
如果看到大量401错误，说明Cookie已过期，需要：
1. 重新登录网站
2. 获取新的Cookie
3. 更新到 `cookies.json` 文件

### 请求失败
- 检查网络连接
- 检查Cookie是否有效
- 适当增加延迟时间

## 配置参数

在 `main()` 函数中可以调整：

```python
crawler.run(
    limit=40,              # 排行榜返回数量
    want_it_ranking_type=2,  # 排行榜类型
    delay=2.0              # 基础延迟（秒，实际会随机变化）
)
```
