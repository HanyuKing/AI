# 电商 Agent 工程实战课

配套 [`../学习路线.md`](../学习路线.md) 的完整代码课程。课程以“电商售后助手”为贯穿项目，按后端工程的学习路径从服务骨架走到可评测、可观测、可部署的 Agent 应用。每章 README 按课件组织：学习目标、概念讲解、代码阅读、课堂实验、课后练习和验收要求。

## 你将学会什么

完成课程后，应能说明一次 Agent 请求的完整路径：谁提供可信用户身份、模型如何提出工具建议、服务端如何校验参数和权限、实时数据与政策知识如何分工、风险动作如何审批、失败如何恢复、效果如何回归评测，以及线上如何定位一次失败调用。重点不是背某个框架 API，而是理解模型外的确定性边界。

代码主线刻意遵循几条工程原则：

1. 模型输出是不可信输入。它必须经过 schema、长度、业务规则和权限检查。
2. 身份由已认证服务上下文提供，用户或模型不能通过参数伪造 `user_id`、租户或角色。
3. 订单/物流等实时事实来自业务工具；政策知识来自 RAG；检索文档不能充当实时状态。
4. 高影响写操作走“草稿 → 人工审批 → 执行”，服务端在执行时重验对象状态并使用幂等键。
5. 离线评测和 Trace 是持续迭代的基础；只看成功 Demo 无法判断回归或安全问题。

## 环境准备

需要 Python 3.11 或更新版本。模型调用、向量数据库、Redis、PostgreSQL 和 MCP SDK 都不是运行基础章节的必需条件；默认假模型让课程离线可跑。

```bash
cd agent/learning_lab
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
python -m unittest discover -s tests -v
```

`pyproject.toml` 中 `.[dev]` 提供 pytest/HTTPX 作为扩展工具；核心回归目前使用标准库 `unittest`，无需额外测试框架。FastAPI 服务通过 Uvicorn 启动，各章命令都从本目录执行。

## 推荐学习节奏

每章先读课件中的概念，再按建议顺序看代码。第一次学习不要直接跳到 `06-production`：后面的整合层有意复用早期模块，只有理解各层责任，才能判断一次错误应该在哪修。每章先运行基线，再运行测试，接着改一个小功能并补一条失败用例。每个练习都留下 README/测试/评测结果作为作品集证据。

真实模型接入只在第 1 章做选修练习：设置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。密钥只经环境变量或正式密钥服务注入，不写入代码、提示词、Trace 或提交记录。MCP 专项通过 `pip install -e '.[mcp]'` 安装额外 SDK。

## 目录约定

每个阶段目录有 `README.md` 与阶段代码包；`shared/` 只放跨阶段的领域类型、配置和本地教学存储，不放模型提示词或章节流程。这样学习者可以把 RAG 或 Agent 编排替换掉，而订单授权规则仍由共享领域服务负责。

本项目使用内存数据和原子替换的本地 JSON 文件讲解流程。它不提供生产级认证、数据库事务、并发锁、模型 SLA、真实 MCP 多租户会话或支付退款能力。每章会指出扩展到生产所需补齐的边界。
